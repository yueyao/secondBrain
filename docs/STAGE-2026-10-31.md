> 用途：把这一阶段的**方案与实现状态**固定下来。后续任何改动都可以对比本文件判断"偏离了多少"。

## 1. 阶段定位

从零搭起了一套**可运行、可测试、可换模型**的 secondBrain 服务端骨架：

- 领域层实现了完整的生产状态机（18 状态 / 24 事件 / 32 条合法迁移）；
- 适配器层接上了真实 SQLite、真实 git、单写者锁；
- 应用层跑通了 `ingest → triage → digest → review → commit` 闭环；
- 模型层完成了路由 / 预算（可选）/ 缓存 / 重试 / 降级 / 契约校验，并接上 DeepSeek（默认 `deepseek-flash`）；
- 有一套 172 例的测试，覆盖从纯函数到真实 HTTP 的五个层次；
- 有一页可交互的审核台（无前端框架，手机可用）与 `/usage` 用量页。

**这一阶段刻意没做的**：启动对账 `Recover()`、prune、decide、golden set、真实模型质量评估。

## 4. 模型层（决策 A：全部来源走云）

- **协议**：OpenAI 兼容 `/chat/completions`；支持任何兼容端点（DeepSeek / OpenAI / Qwen / OpenRouter / vLLM / Ollama 等）。
- **默认模型**：DeepSeek `deepseek-flash`（关闭 thinking，便宜快）；`deepseek-v4-pro` 保留为手动升级项。
- **成本**：不设硬上限，只计量；价格表未填时成本显示 0，tokens 始终准确。
- **稳定性**：超时/限流/5xx 重试后降级；契约违反重试一次；拒答不重试；缓存命中不计费。
- **可解释**：每条草稿带 provenance（profile / model / prompt 版本 / tokens / 是否缓存 / 降级链）。

## 7. 已知缺口（下一阶段入口）

1. `commit_intent` 两阶段与启动对账 `Recover()`：断电恢复类测试缺失。
2. golden set（30–50 篇标注）与评测脚本：换模型的质量护栏。
3. cache-hit 单价与 off-peak 时段计价：目前单一定价，偏保守。
4. prune / decide 用例。
5. 真实模型跑首篇后的质量与成本基线。
