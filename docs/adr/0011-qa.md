# ADR 0011：问答链（Q-A）作为独立只读能力

- 状态：已采纳
- 日期：2026-11-04
- 相关：ADR 0005（模型接入）、ADR 0009（文章版本）、ADR 0010（去 AI 味）

## 背景

调研（知识库 × AI 写作）里，`ljg-qa` 的"信息提问机"是高频被引用的方法：把材料抽成 Q-A 链，
Q 切要害（为什么成立/代价/边界），A 四段（结论/形式化/论证步/边界），用于选题、审稿与自测。

我们的文章版本链只记录"正文"（ai_initial / ai_refine / deai / restore / manual_edit），
把问答链塞进版本链会污染 diff、导出与定稿语义；而问答链本身也不是"文章"。

## 决策

1. 新增端口 `QaPort`（`packages/contracts/src/ports/qa.ts`），只声明 `QaRequest/QaResult`；
2. `@sb/agent-runtime` 新增 `QaRunner`（text 模式、路由/预算/重试/降级/记账/provenance），
   新增 `AgentTask = 'qa'`；没有显式 `policies.qa` 时沿用 digest 策略（与其它任务一致）；
3. 本地契约只校验"问题数量 + 每问四段结构"，不合规回喂原因重试一次，再不合规则拒绝；
4. `@sb/app` 新增 `qaTopic` / `qaArticle`，只读，不写库、不改文章版本；
5. 入口是独立页 `/qa`：选主题或文章 → 生成 → 页面展示；文章详情与主题地图提供入口链接；
6. mock 模式用 `MockQa` 生成确定性问答链，保证离线演示与 e2e 可测。

## 后果

- 问答链不进入文章版本链，diff/定稿/导出语义不变；
- 每次生成都是一次模型调用（有成本、有预算），当前不持久化；后续若需要可加缓存表；
- 契约只保证结构，不保证"问题切要害"；质量仍由提示词与人工判断兜底（与 ADR 0010 的取舍一致）。
